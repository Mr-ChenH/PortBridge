# PortBridge 首版需求

> 状态：已按用户授权完成首版软件实现、独立审核、修复、复验及本机便携部署；Qt/C++、TCP/UDP、约2.5G网口为既定约束。Windows/IPv4首版功能映射和证据见 `08-acceptance-report.md`。真实串口、两机2.5G、干净Windows及声明持续负载仍未物理验收，用户原Qt Socket程序的丢失原因尚未定位。

## 1. 产品目标

帮助嵌入式及设备测试人员完成串口、TCP/UDP 连接、手动/周期发送、数据观察和日志留存。用统一的操作方式减少在多个调试工具之间切换。

## 2. 首版边界

- 串口、TCP 客户端、TCP 服务端、UDP；IPv4 首先验收。
- 共用文本/HEX、时间戳、搜索、统计、周期发送、简单快捷命令、日志和配置。
- 面向 2.5G 场景增加独立网络 I/O、高速模式、显示抽样、二进制采集与丢失诊断；完整方案见 [高速通信方案](10-high-throughput-plan.md)。
- TCP 服务端至少允许多个客户端接入、独立识别及定向/广播发送。
- 首版可仅开放一个活动通信会话；底层数据和任务按会话隔离。多会话 UI 列入增强阶段。
- GBK/GB18030、多命令序列、串口网络转发、文件发送和重连列入增强阶段；如实际设备依赖这些功能，应调整首版范围。
- 完整协议分析、Modbus、波形、脚本、ANSI 终端模拟、串口旁路监听和原始网络抓包不纳入当前首版建议。

## 3. 用户故事

- 作为嵌入式开发人员，我需要打开 USB 串口，发送 HEX 命令并查看原始返回字节。
- 作为网络设备测试人员，我需要模拟 TCP 客户端或服务端，选择对端发送并判断响应来源。
- 作为 UDP 设备调试人员，我需要从指定本地端口收发数据报，知道发送来源及数据报长度。
- 作为问题排查人员，我需要保留包含时间、方向和原始字节的日志，以便复现分析。
- 作为重复测试人员，我需要按指定周期发送命令，随时停止，断线后不继续积压发送。

## 4. 功能需求

| ID | 需求 | 验收要点 |
| --- | --- | --- |
| FR-001 | 枚举、刷新串口并显示可用设备信息 | 空列表可理解；手动端口输入可用；缺失厂商信息不影响连接 |
| FR-002 | 配置串口波特率、数据位、校验、停止位及流控 | 常用参数和自定义波特率可输入；设备不支持配置时明确报错 |
| FR-003 | 打开/关闭串口并展示错误 | 占用、设备不存在、配置失败和拔出均可观察；NoError 不当作异常 |
| FR-004 | TCP 客户端连接 IP/域名及端口 | 显示连接过程和结果；可取消连接；连接超时不阻塞 UI |
| FR-005 | TCP 服务端绑定并监听 | 端口占用提示；停止监听时关闭首版管理的客户端并停止发送任务 |
| FR-006 | 管理服务端客户端 | 显示连接 ID、地址和状态；接收来源正确；支持选定客户端发送、断开和广播 |
| FR-007 | UDP 绑定与发送目标分别配置 | 显示实际本地端口；来源地址与数据报边界可观察；目标不存在不误报在线 |
| FR-008 | 按需选择本地 IPv4 地址 | 显示可用地址；绑定失败提供原因；实际地址/端口可见 |
| FR-009 | 文本和 HEX 输入、显示独立设置 | AA BB 与 AABB 可转换；非法字符/奇数位禁止发送；文本模式明确编码 |
| FR-010 | 原始字节保存与显示切换 | 缓存范围内切换 HEX/文本基于原始数据，不从显示文字倒推 |
| FR-011 | 换行设置与发送字节数 | 无/CR/LF/CRLF 可选；发送结果与预览一致 |
| FR-012 | 展示时间、方向、连接来源与错误事件 | 可区分 TX/RX/SYSTEM；软件时间戳到毫秒；未分帧的读取结果不误标为报文 |
| FR-013 | 查看、复制、搜索、自动滚动和清空 | 文本/HEX 搜索语义明确；清空显示不清串口接收缓冲或停止日志 |
| FR-014 | 暂停显示 | 接收、统计、日志继续；显示缓存达到上限时标注裁剪；可恢复显示 |
| FR-015 | 统计和状态 | 展示 TX/RX 字节、速率、待发送量；单独重置统计；本地发送完成不等同对端确认 |
| FR-016 | 定时重复发送 | 设置间隔和有限/持续次数；界面可停止；断线停止；队列拥塞不会无限增长 |
| FR-017 | 发送历史及命名快捷命令 | 保存内容、格式、编码、换行；选择后可预览并主动发送；不默认开机自动发送 |
| FR-018 | 连续日志与导出 | 普通模式文本/结构化导出；高速模式二进制原始记录及索引，离线可恢复方向/来源与报文边界；轮转及写入失败可见 |
| FR-019 | 用户配置保存 | 保存连接参数和界面偏好；命令/方案支持带版本的 JSON；重启不自动连设备 |
| FR-020 | 完整停止与退出 | 停止定时任务和连接，有限时间内完成日志收尾；写入失败/未完成记录可观察 |
| FR-021 | 高速接收与抽样显示 | 原始接收独立于 GUI 刷新；显示样本、速率和队列状态，明确未展示量；能配置记录大小/时长 |
| FR-022 | 丢失与过载诊断 | 分别统计应用收到、队列丢弃、接收截断、记录失败和显示抽样；仅在协议/测试数据有序号时分析端到端缺失，平台不可观测计数标为未知 |

## 5. 非功能需求

| ID | 要求 | 说明 |
| --- | --- | --- |
| NFR-001 | UI 保持响应 | 网络 I/O 独立执行；GUI 不进行收包、同步记录或逐包处理；显示以有限批次抽样更新 |
| NFR-002 | 内存与队列有界 | 接收处理、待发送、显示、日志均设上限及超限策略；不能仅限制行数 |
| NFR-003 | 数据含义准确 | 原始字节与显示分离；高速管线允许复用数据块/缓冲句柄，避免逐包转换成界面对象；TCP/串口读取块不是帧，UDP 保留数据报边界和来源 |
| NFR-004 | 明确发送结果 | 区分请求、排队、本地写出和业务响应；错误与部分接受可处理 |
| NFR-005 | 会话隔离 | 不同 TCP 客户端的解码器、缓存和连接身份独立；后续多会话可复用 |
| NFR-006 | 可恢复错误 | 无设备、权限不足、断线、端口占用、日志失败不会导致崩溃或挂死 |
| NFR-007 | 可复现配置 | 导入验证版本、字段类型与范围；使用安全写入避免损坏原配置 |
| NFR-008 | 清晰的运行状态 | 状态文字和动作一致，错误不只依赖颜色；连接、监听、绑定状态区别明确 |
| NFR-009 | 平台封装 | 首版 Windows 优先建议；系统特有行为集中处理，不承诺未经验证的平台兼容 |
| NFR-010 | 可部署 | 干净 Windows 目标系统验证 Qt 运行时、平台插件和必要模块 |
| NFR-011 | 2.5G 负载验证 | 两台真实机器/网卡验证 TCP 吞吐及 UDP 的不同包长/PPS、突发；后端选型依据实测 |
| NFR-012 | 网络后端可替换 | 与 Qt UI 解耦，优先评估 Asio；Qt Socket 对照、原生实现必要时优化；不得以换库代替性能验收 |
| NFR-013 | 过载结果明确 | TCP 使用背压或报告终止，不静默丢字节；UDP 队列饱和执行明示策略；记录丢弃与显示抽样分别计数 |

### 性能验证与候选基线

用户已明确约 2.5G 网口；原先 TCP 1 MiB/s、UDP 1000 报/秒仅适合作为功能冒烟负载，不能作为高速验收门槛。正式性能范围按包长、PPS、吞吐、突发、方向及日志条件定义，见高速通信方案。

- 串口：115200 bps 连续运行 1 小时，并按实际设备支持情况验证更高波特率。
- 网络：两台真实机器的 2.5G 链路，分不同负载比例验证 TCP 和 64/256/1024/1472 字节 payload 的 UDP，并记录实际达到的 MB/s/PPS；是否双向满速需补充。
- 分别测仅接收、接收+二进制记录、接收+UI 抽样、全部开启，确定各条件下的持续吞吐和可复现丢失率；不预先承诺任意负载 UDP 零丢失。
- TCP 服务端：至少 4 个客户端功能隔离验证；高速多连接的累计负载单独设定。
- 建议显示保留最近 10 MiB 原始样本且至多 5 万条记录，任一上限触发裁剪；高速模式不缓存全部原始流量到 UI。
- UI 操作目标约 200 ms 内响应，最终在声明负载下定义测试方法；收包正确性不得依赖 UI 更新速度。
- 日志容量、轮转数量和队列预算据持续磁盘速度确定；约 300 MB/s 原始记录约需 1.08 TB/小时，不能用 HEX/JSON 满速实时落盘替代二进制记录。

正式目标尚需典型报文大小、包率和实际设备负载数据。TCP 数据一致性和 UDP 丢失率分别验收，内核/网卡丢失、应用丢弃、记录失败和显示抽样分别报告。

## 6. 数据约定

- 连接参数：传输类型、串口参数或网络绑定/目标参数。
- 命令：名称、原文、发送模式、编码、换行、周期设置；定时运行状态不持久化恢复。
- 收发记录：版本、序号、会话 ID、连接 ID、时间、方向、传输类型、端点、原始 payload、事件类别。
- 空 UDP payload 合法；空串口/TCP发送可提示无内容。
- 原始记录和文本展示分离；普通模式结构化导出可用 HEX/Base64，高速模式使用二进制 payload 与元数据索引，离线转换。
- 应用不涉及账号、云服务或支付；本地设备和文件权限由操作系统决定。

## 7. 必须处理的边界场景

1. 打开串口失败、被占用、USB 设备拔出及 COM 号变化。
2. 不完整 UTF-8 字符跨多次读取；TCP 多个客户端独立编码状态。
3. 网络绑定失败、连接拒绝/超时、远端正常或异常断开。
4. TCP 对端以不同块大小收发同一串字节；显示与日志保持字节一致。
5. UDP 零长度数据报、多个来源和接收过载；不把数据报合并成一段流。
6. 高频定时发送超过链路速度、文件系统写入变慢、日志磁盘空间不足。
7. 暂停显示后缓存裁剪、清空显示时通信仍继续。
8. 修改连接参数、切换通信方式和退出时旧任务完整终止。
9. 导入未知 schemaVersion、非法 HEX、错误端口及损坏配置。

## 9. 后续待定事项

| 事项 | 当前建议 | 对范围的影响 |
| --- | --- | --- |
| 发布平台 | Windows 首发，其他平台后续验证 | 编译器、串口差异、打包与测试 |
| 设备文本编码 | ASCII/UTF-8 起步 | 若必须 GBK，编码兼容模块进入首版 |
| 产品主要场景 | 通用设备调试 | 工业场景可能提前 Modbus；网关场景可能提前转发 |
| 并发会话数量 | 首版一个活动通信会话，TCP 服务端多客户端 | 若需要多串口同时工作，多标签应进入首版 |
| 串口网口互转 | 第二阶段 | 若核心目标为协议网关，需要重新定义桥接首版 |
| 高速负载与记录时长 | 已知约 2.5G 网口；包长/PPS、突发、单/双向及持续记录条件待定 | 网络后端、I/O 并行度、缓冲预算、磁盘容量与正式验收 |
| 丢失位置 | 用户报告报文丢失，尚无测试证据定位 | 需对照发送端、网卡/内核、应用接收、解析及日志 |
