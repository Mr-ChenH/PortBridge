# HTTP项目交互与设置布局优化

本轮用户先要求优化项目设置布局，随后指出HTTP创建入口强制填地址、方案/名称/项目概念混乱。已合并实现http-interaction-1，当前代理实施与自审，无新增独立审核声明。

## 产品行为

HTTP界面明确“项目 → 环境 → 请求”：项目收纳相关接口并共享环境/变量/认证，环境配置服务地址和运行上下文，请求保存名称/方法/路径/头/Body及检查规则。请求名称用于在列表中识别接口，与地址无关。

统一入口改为“新建调试项”，按当前工作台默认类型。HTTP选择只输入请求名称，不显示地址输入，创建到当前项目并默认{{base_url}}/。编辑器提示补接口路径，也允许完整URL；启用的固定URL不会隐式改写。WS仍要求地址并校验；原串口/TCP/UDP连接方案保持。HTTP新建/保存/搜索/空态/保存结果明确“请求”，WS使用“连接”。

新建项目说明容器用途，创建成功后直接打开当前环境设置，填写环境名称与base_url；取消设置保留明确创建的空项目，与原新环境创建语义一致。创建、浏览、保存和配置不通信，未配置base_url时发送前拒绝；请求/资源/草稿保护保留。持久化schema、ID、导入/导出、秘密隔离、TLS校验、取消围栏、顺序联调均沿用原实现。

## 布局

项目设置由顶部五页签改为左侧分类导航、右侧标题/说明及编辑区、底部保存/取消。项目名称放入项目变量页，避免占据所有页上方。保留原QTabWidget对象/索引，通过导航同步确保旧入口/错误定位可用；鼠标、键盘和程序切页均检查。

默认980×660并参考当前屏幕可用区域，支持740×500和拖动调整。每页独立滚动，较长浏览器页在紧凑窗口中滚动，底部保存区不跟随滚动。表单统一标签对齐和间距；变量表40行高/交替底色；浏览器范围、平台、语言并排，预览等宽字。没有新增自动保存。
