# HTTP 一请求一条记录 · http-history-1

发送HTTP请求曾先新增START提示、完成再新增响应，容易被理解为两条消息。现在发送生成“请求中”记录；响应、错误或取消用同一operationId更新原记录，保留记录ID与开始时间。只有再次主动发送才增加下一条。列表三列为“时间”“状态”“请求 / 响应”，状态显示请求中、已响应、失败、已取消。结果摘要含方法、实际HTTP状态码、耗时与正文大小；非2xx仍是已响应并使用提示色。

## 实现与检查

HTTP开始记录携带活动请求ID。既有add逻辑查找同一HTTP操作，扣除原成本、保留身份并替换内容，再按既有16MiB/64条预算淘汰。协议错误/取消也绑定活动请求；顺序执行步骤间没有在途请求时不制造额外请求记录。clearHistory不取消通信，最终响应可作为清空后的记录出现。完整结果仍由原生产客户端提供，latestResponse、遮蔽预览、响应提取、断言、顺序执行及WS事件模型保留。

首次构建通过，但新增回归发现查找使用了std::move后已空的operation参数，导致未合并。改为读取新记录的operationId。UI模型本来通过定时器异步刷新，测试补齐等待列表状态的条件，覆盖真实稳定状态。首次3通过/3失败及执行源码保留在 `before-operation-id-fix/`，最终证据为 `final/`，旧失败未改写。
