# HTTP 第二期：请求断言与项目顺序联调

用户选择“请求断言与项目顺序联调”，授权继续实现。第一期 `http-project-1` 保留；本期目标 `http-sequence-1`，当前代理实现与自审。

## 要求与验收

| ID | 行为与验收 |
|---|---|
| HS01 | 已保存HTTP请求可配置最多32条断言：状态码、响应头、JSON点/数组路径；equals严格类型、exists、contains（字符串）三种关系。保存/导入先校验，旧请求没有断言时兼容。 |
| HS02 | 手动发送后的权威响应计算断言，显示逐项通过/失败；不依赖预览、不更改原始响应。报告不包含实际响应字段、预期值或认证数据。 |
| HS03 | 项目顺序联调选择已保存请求，可调整顺序，最多128步，冻结请求定义。登录提取后再解析下一步，使用当前项目/环境；不自动登录、运行或重试。 |
| HS04 | 明确点击运行才通信；错误默认停止，可选择继续。网络、解析、提取或断言失败均失败，非2xx默认失败；停止取消当前操作，未执行步骤标记跳过。最多10分钟运行时间。 |
| HS05 | 整段运行锁定环境/项目和编辑，步骤间仍占有HTTP资源。旧活动须经原资源确认，确认期间身份变化保留旧活动；切换资源、Esc和退出可以取消整个运行，晚回调不继续。 |
| HS06 | 展示有界步骤结果、断言详情和成功/失败/取消/跳过计数，JSON导出元数据与结果，无请求/响应字节、变量值和实际凭据。结果不自动持久化。 |

## 设计与实现顺序

1. 可复用请求解析与断言模型；本地实际响应和类型/路径/容量验证。
2. 顺序运行控制器：HTTP会话增加运行资源身份，异步单步发起，版本/代际复核，停止与总时间预算；页签结果、选择/排序对话框。
3. 冻结输入下完成真实登录→认证查询、失败策略、取消/晚响应、活动互斥与导入导出/脱敏回归。
4. 深浅/紧凑与100/125/150%软件缩放截图，完整回归、操作文档，独立部署与压缩/解压哈希，保留第一期交付。

断言失败仍可在匹配2xx响应后执行已经配置的提取：提取规则全部成功才原子提交，与第一期一致；失败策略决定是否发起下一步。模板/断言规则在每步发送前验证。外部直接修改store时按revision终止，不因UI锁定假设身份不变。

项目导出保留请求断言，不包含运行计划或报告。运行计划由用户选择，不增加持久脚本、循环、并发、OAuth、自动刷新或运行重试。继续复用原HTTP客户端、TLS校验与工作流资源确认，不建立第二条隐式网络通道。
