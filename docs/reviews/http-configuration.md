# HTTP 配置重构验收 · http-configuration-1

HTTP 项目设置现在统一编辑当前环境、项目变量、公共认证和生效变量。创建环境后直接进入地址/变量配置；运行值与定义分开展示，编辑或保存定义不再把登录提取值混入长期定义。公共认证按方式展示所需字段，继承请求显示项目认证类型和当前环境。

## 关系与使用

| 内容 | 归属与用途 |
|---|---|
| 项目 | 请求/分类、共享默认变量、公共认证及多个环境。 |
| 环境定义 | 当前环境的地址与变量；同名定义覆盖项目默认值。服务地址是既有base_url变量。 |
| 运行值 | 登录提取或敏感输入；属于当前项目/环境，优先于定义，不持久化或导出。 |
| 请求 | 保存未展开模板；明确发送时冻结上下文并解析。URL用{{base_url}}引用地址；认证明确继承/自行设置/无认证。 |

用户从“项目设置”统一配置，“配置环境”直接打开同一窗口的环境页。管理菜单保留项目/分类/环境CRUD与导入导出；新建/复制环境立即打开配置。创建是独立明确动作，取消随后的设置仍保留新建空环境，侧栏显示地址未配置。生效变量表显示已保存配置的来源、状态和运行更新时间，敏感值遮蔽；清除单个/全部运行值先加入草稿，保存才应用，取消保留原值。

## 实现与自审

`HttpConfigurationDialog`提供四个页签；可复用定义编辑器保留文本/数字/布尔/JSON类型，只从定义加载值，不从运行数据填充。已有非文本/敏感base_url保留在原变量表，避免服务地址快捷框改变其类型。敏感名称自动遮蔽输入，变量选择只列名称。Bearer自动加前缀并拒绝重复前缀，Basic只显示账号/密码，预览始终使用固定占位符。

`HttpProjectStore::saveConfiguration()`先验证projectId/environmentId/revision，构造定义与运行候选，执行原有变量/项目/全局预算，再一次commit；成功后才发布运行候选。失败不留下名称、认证、变量或运行清除的部分修改。旧setter、schema2、请求认证索引0/1/2/3、解析/模板冻结/序列资源边界保持兼容。定义删除不会隐式撤销独立提取值，用户可在生效变量页显式清除。

本轮为当前代理实施与自审。依据复用既有官方调研（15-http-project-research.md），结合实际store/panel/resolver和测试数据流；没有新增独立代理审核声明。需求和实施路径见 [计划](../project-factory/21-http-configuration-refactor.md)。

## 最终验证

源码冻结后构建17.787秒，无编译warning/error；全量CTest **10/10、175.566秒**。HTTP普通测试 **41通过、0失败、3受控截图跳过**，原生Qt软件因子1/1.25/1.5分别 **10通过、0失败、0跳过**。数量包含QtTest初始化/清理。

六个新增功能用例实际验证：

- 项目/环境/运行值优先级，重复变量时原子拒绝，旧revision拒绝，清除后回退、环境隔离及重新加载。
- 定义编辑框不显示敏感运行值，取消完全保留；按认证方式显示字段、重复Bearer前缀拒绝、保存后模板和地址正确。
- 用测试私有INI路径变成目录制造真实QSettings写入失败；内存定义、运行值、revision和缓存中原保存意图保持原样。外部已破坏的测试路径不被描述为磁盘原文件完整性认证。
- 真实触发新建环境菜单，输入名称后自动进入配置、填写地址、保存与重新加载；服务收到0个请求。
- 打开设置后切换上下文，保存被拒绝，原状态保留。
- 两个真实本地HTTP服务分别收到对应环境Bearer；Basic收到实际Base64账号密码；请求无认证不生成Authorization；持久化内容不包含合成敏感值。

原生截图覆盖四页、Bearer/Basic、深浅主题及工作台。首次功能回归10/10通过，但人工查看发现深色pane/tab仍使用系统浅色背景，修正后重新冻结与完整回归。首次结果、原截图及执行源码保留在 `before-theme-fix/`，最终使用 `final/`；未把视觉问题阶段描述为最终交付。可离线打开 [真实界面图集](../validation/http-configuration/gallery.html)。
