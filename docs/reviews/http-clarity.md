# HTTP交互一致性审核与修正

审核对象为当前http-interaction-1后的真实原生Qt实现，沿项目创建、环境配置、HTTP请求创建/草稿/保存、分类筛选、导入导出、浏览器配置、WS和设备通信入口检查。当前代理审核/实施，不是新增独立代理审计；不宣称穷尽全部交互。

## 发现

| ID | 优先级 | 混乱之处 | 修正 |
|---|---|---|---|
| HC01 | P2 | 两个“新建请求”入口，一个立即保存，一个只清空编辑器建立未保存草稿。 | 顶部类型选择明确“创建并保存请求”，编辑器为“新建草稿”；空态/确认/说明同步。保存提示明确更新当前项，改名不会另建。 |
| HC02 | P2 | 从设备工作台进入HTTP创建时，没有显示保存到哪个项目/使用哪个环境。 | HTTP创建对话框显示项目和环境名称，环境说明为发送时的地址/变量上下文；WS不显示HTTP归属。 |
| HC03 | P2 | 工具条“导入/导出”和管理菜单同名操作的范围不明显。 | 工具条为“导入请求/导出请求”（WS为连接）；提示单项/编辑器与整项目区别，导出当前编辑含未保存内容。 |
| HC04 | P2 | 分类无条目时提示“项目没有请求”，创建请求又默认未分类，在当前分类下可能看不见。 | 区分项目为空、分类为空、搜索无匹配；新建保存请求和新建草稿沿用所选分类，“全部请求”默认未分类。 |
| HC05 | P2 | 只要base_url存在，就声称已定义；空文本、数字或未解析模板不能真正用作地址。 | 概览区分未配置/类型无效/待补齐/已配置；只在本地展开校验，不探测目标。空或非文本地址发送给出配置环境提示，0通信。 |
| HC06 | P2 | 项目名称位于“项目变量”，用户不易发现重命名入口。 | 设置分类更名“项目与变量”，菜单“项目名称与共享变量”；保留原索引、对象ID和数据schema。 |
| HC07 | P2 | 项目/环境创建后取消配置仍保留新对象，只有文档说明，界面容易把取消当成撤销创建。 | 新项目、新环境和环境副本设置窗口显示创建已完成及取消作用范围。 |
| HC08 | P2 | 主入口术语改好，但导入/校验/退出提示仍出现HTTP“方案”；WS地址称“请求地址”。 | 手动HTTP/WS页错误统一请求/连接配置，退出明确保存的请求/连接；WS使用“连接地址”。设备原始连接方案术语保持。 |
| HC09 | P3 | 浏览器范围更改不是即时更换；关闭自动头仍可引用变量，用户可能误以为已生效/删除。 | 按钮“随机生成预览”，提示保存后应用、范围不自动修改既有配置；启用勾选提示关闭不删除变量。 |
| HC10 | P3 | 原生工作台首次空闲状态同时写“尚未发送 / 已结束”，WS同时写“未连接 / 已关闭”，把不同历史状态混为一条。 | 空闲明确“未在发送请求”或“未连接”；已有响应仍显示真实HTTP状态/耗时，错误与历史终态保持。 |

本轮没有发现需要改数据schema或协议栈的证据。仍需理解的规则：完整URL不会自动使用环境地址；生效变量显示已保存配置，而不是未保存设置草稿；项目/环境创建与随后配置是两个明确步骤。这些在界面/指南中说明，本轮保留行为，避免静默重写请求或持久化秘密。设置变量优先级、公共认证继承、登录提取、断言/顺序联调的既有合同保持。
