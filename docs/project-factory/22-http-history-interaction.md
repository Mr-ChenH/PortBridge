# HTTP 请求历史交互优化

用户指出一次HTTP发送显示START事件和响应两条消息。改为一请求一记录：以operationId匹配并替换，保留记录ID与开始时间。状态请求中→已响应/失败/已取消；4xx/5xx保留实际响应，不等同网络失败。HTTP列表列名改为状态、请求/响应；WebSocket继续使用事件/收发消息。

要求：真实延迟请求只有一条记录；完成、超时、容量拒绝、取消均复用原记录；晚回调不复活取消请求；拒绝校验/确认不添加记录；连续发送新增一条；查看旧响应不被最新更新抢走；清空与16MiB/64条预算正确；顺序联调与完整原始响应/凭据遮蔽保持。

实现：ProtocolDebugSession::add对HTTP非空operationId原位身份合并，替换时先扣旧成本，再按既有预算收缩/淘汰；HTTP取消使用活动请求ID，步骤间仅取消序列不制造请求记录。最终结果仍通过同一changed信号刷新。Timeline把内部事件类型映射为中文状态，并区分非2xx响应颜色。

验证完成：三个新增真实HTTP回归及原有晚回调隔离用例通过；最终全量CTest10/10，协议普通46通过/1受控跳过，原生软件100/125/150%各7通过，源输入91项冻结。首次移动后操作ID查找失败及复验过程保留，详见 [验收](../reviews/http-history.md)。当前代理实施/自审，旧版本证据保留，范围不包含无关协议/硬件性能修改。
