# HTTP项目交互与设置布局优化

用户先要求优化HTTP项目设置布局，随后指出创建HTTP还要求地址、“方案名称/方案/项目”含义混乱。这是同一轮扩展需求，目标是落实清晰的“项目 → 环境 → 请求”层级，连同设置布局一并交付。

## 行为

- 项目收纳一组接口请求，提供共享环境、变量和公共认证。新建项目说明此用途，创建后直接打开当前环境设置，继续填写环境名称/服务地址。取消后保留明确创建的项目，与已有新环境流程一致。
- 环境保存服务地址base_url、环境变量、运行值和浏览器配置；切换环境只改变模板上下文，不通信、不重写固定URL。
- 请求名称标识一个接口，如“用户登录”“查询订单”。HTTP界面的新建/保存/搜索/空态/提示统一请求术语；设备收发保留连接方案，WS使用连接。
- 顶部统一入口为“新建调试项”。HTTP卡片只要请求名称，不显示/强制填写地址；创建到当前项目并使用{{base_url}}/模板。请求编辑器填写接口路径，环境提供地址；完整URL仍可用。WS保留连接地址校验。进入HTTP/WS工作台后入口默认对应类型。
- 新建/保存未解析模板不通信，发送前仍验证变量、URL、预算和冻结身份。未配置服务地址时拒绝发送。复制/导入/旧库及敏感运行值规则不变，不换协议或schema。

## 设置布局

左侧分类导航，右侧标题/说明/表单与预览，底部固定保存/取消。项目名称移到项目变量页，避免占据每页。导航保留原QTabWidget索引和既有对象名以兼容入口/错误定位；鼠标/键盘与程序切页同步。

默认980×660，按屏幕可用区域限制，支持740×500紧凑尺寸及拖动调整。各页独立滚动，长表单不撑高整个窗口。统一表单间距、变量行高、交替背景；浏览器三个范围并排，请求头预览用等宽字体。草稿及原子保存沿用原流程。

## 验收

真实HTTP新建项目→配置环境→无地址创建请求→用模板发送→切换第二环境且模板保持→无地址环境拒发。HTTP/WS统一入口校验、旧草稿/活动保留；原子设置、敏感变量及浏览器配置回归。原生深浅、Qt软件1/1.25/1.5，五个页面/Basic/紧凑尺寸、导航鼠标键盘及保存按钮可达；完整相关回归及独立部署。
