# HTTP项目工作台技术与实施计划

## 模块与数据

Qt Widgets、C++17、现有WorkflowProtocolClient保持。新增HttpProjectStore负责项目/文件夹/环境定义、运行变量、作用域和解析。HTTP页通过稳定projectId/environmentId/requestId绑定上下文；已有请求UUID沿用，旧entries迁入默认项目。QSettings保存有界版本化项目定义，不保存响应token；QSaveFile导出项目。先校验完整输入，再替换或提交；定义写入失败回滚，运行token不被文件遮蔽标记覆盖。

变量优先级在UI中明确：当前环境运行值 > 当前环境定义 > 项目定义。项目隔离，不引入跨项目全局token。第一期项目默认认证、请求继承或覆盖；文件夹负责归类，层层认证/变量覆盖作为扩展，避免第一期混淆来源。默认项目不启用认证，因此旧请求行为一致。

发送流程：从编辑器取得模板 → 捕获项目/环境及变量版本 → 解析变量与认证 → 按字段进行query/form编码或JSON转义/类型处理 → 现有校验（URL、CR/LF、重复头、Body、容量）→ 资源确认并复核上下文 → 冻结实际快照 → 真实客户端发送。保存模板不要求已登录；只验证模板结构、字段上限和语法，不把变量值固化到文件。

响应流程：从权威原始response取得JSON/headers → 核对operationId/epoch与绑定上下文 → 2xx且规则有效 → 有界点字段/数组索引提取 → 所有规则成功后原子写入运行变量 → 更新遮蔽状态与提示。规则失败保留旧值并明确说明；不从32K遮蔽预览提取。旧请求历史重选不再次执行提取，失败/取消不会更新运行值。

## 交互

HTTP方案侧栏升级为项目选择、文件夹分类与请求列表，提供项目管理和新建分类。请求区域显示当前项目/环境，提供环境变量管理与运行值清除；认证增加“继承项目”，Body保留原有模式，增加“响应提取”页签。模板、缺失变量和认证来源可检查；变量编辑与提取均提供解释，不将实现细节堆到发送流程。活动期间锁定运行上下文，页面浏览仍保留网络活动。

## 分阶段实施

- P1：项目/环境/变量模型、边界、模板解析、提取；单元覆盖隔离、更新原子性、JSON转义与版本导入。
- P2：HTTP项目/文件夹/请求归属、环境及公共认证UI；迁移旧库，保存/导出保留模板，统一新建入口选择当前项目。
- P3：响应规则与实际登录→业务请求闭环，取消/失败/过期身份、默认凭据遮蔽；本地服务器核对真实URI/Authorization/Body。
- P4：相关UI/工作流回归、原生深浅/紧凑/软件缩放、独立部署与ZIP哈希；保留connection-ui-1交付。

本轮由当前代理实现与自审，不声称独立多代理审查。新用户授权适用于上述明确范围；若后来改变范围，更新这些补充文档，不覆盖历史验收记录。不得将research成功、源码编译或原型当作已交付；以最终测试与部署回执为准。
