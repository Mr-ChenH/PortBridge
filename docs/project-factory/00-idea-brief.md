# PortBridge 项目概要

## 已知目标

开发串口、网口调试助手，技术路线由用户明确指定为 Qt + C++。已完成需求调研、界面设计及浏览器交互原型；用户随后授权使用 Orca、最多三个子 agent 实现并审核修复正式 Qt 应用，当前已有 Qt Widgets/CMake 源码及 Release 构建。用户进一步明确 TCP、UDP 均需支持，网口约 2.5G，并报告遇到报文丢失；具体丢失原因尚未定位。

## 仓库情况

初次检查时目录仅包含 `.pi/`；现已形成 docs/、include/、src/、tests/、tools/、scripts/ 和 CMake 配置。当前目录尚未初始化为 Git 仓库；本轮未创建 Git 历史。

## 目标用户与场景

- 嵌入式开发人员：调试 MCU、传感器、USB 转串口设备。
- 工业设备开发及测试人员：调试 RS-232/RS-485 和网络设备的自定义协议。
- 软件测试人员：模拟 TCP 服务端/客户端、UDP 对端，重复发送命令并记录结果。

## 建议定位

面向日常设备联调的通用桌面通信工具。第一版完成连接、收发、观察、记录、重复测试的闭环；后续以串口与网络转发、多会话和协议解析作为增强方向。

## 已确定与暂定事项

| 项目 | 状态 | 内容 |
| --- | --- | --- |
| 技术语言 | 已确定 | C++ |
| GUI 框架 | 已确定 | Qt |
| 产品类型 | 建议 | 桌面调试工具 |
| 首要平台 | 暂定 | Windows，代码结构保留 Linux/macOS 适配能力 |
| 网口含义 | 暂定 | TCP/UDP 套接字通信，不涉及以太网原始帧抓取或网卡驱动 |
| Qt UI 技术 | 建议 | Qt Widgets |
| 网络场景 | 已确定 | TCP + UDP，约 2.5G 网口；实际吞吐、包长/包率与突发形态待测 |
| 网络核心 | 建议 | 与 Qt UI 独立；优先评估 standalone Asio，原生 Winsock/IOCP 等按压测需要引入 |
| 高速模式 | 建议 | 首版独立 I/O、显示抽样、二进制记录及丢失诊断 |
| Qt 版本 | 待定 | Qt 6；6.8 可作为兼容基线候选，具体版本依据本机 SDK、发布平台和维护安排确定 |
| 应用界面语言 | 建议 | 中文优先，文本预留 Qt 国际化接口 |

## 后续影响范围的事项

目标操作系统、是否必须支持 GBK/GB18030、是否以 Modbus 为核心、串口与网络转发是否进入首版、预期同时会话数，尚未由用户确认。已知 2.5G 接口不等于已测吞吐；典型包长、每秒包数、是否双向满速、日志时长及丢失位置仍需明确。高速接收不再采用 GUI 线程中的网络 I/O 建议，细节见 `10-high-throughput-plan.md`。

这些事项不阻碍本次调研。文档中的分期、技术组件和性能数值是建议，不能视为已经批准的实施范围。
