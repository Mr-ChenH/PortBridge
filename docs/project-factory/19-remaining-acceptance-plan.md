# 剩余验收执行计划

> 后续 **ui-latency-fix-1** 已关闭本机声明负载的RA-UI01；UDP/TCP五分钟心跳152/43ms，逐字节采集、实际跨屏及主动GUI停顿复验通过。见 [修复计划](20-ui-latency-fix-plan.md) 和 [验收报告](../reviews/ui-latency-fix.md)。下列计划与执行结果保留补充验收当时的快照；外部条件限制不变。

本轮依据 [全项目完成度审核](../reviews/project-completion-audit.md) 和用户“根据审核的结果，将没有完成的任务完成”授权推进。用户明确目前只有本机；不把缺少设备的验收用localhost替代。软件基准保持 `http-sequence-fix-1`，增加可复用的可选验收工具与实际运行证据。

执行入口：[剩余验收指南](../remaining-acceptance-guide.md)。最终状态：[本轮验收报告](../reviews/remaining-acceptance.md)，其机器回执记录通过、未通过、阻塞及源/包哈希；保留所有失败和探针迭代证据。

执行结果：RA01关闭；RA02接收/实盘一致性通过，响应部分未通过；RA03实际三屏100%/125%DPR同步通过（整个UDP跨屏套件因心跳228ms未通过）；RA04四种阻塞销毁/退出通过；RA05主动500ms停顿期间原始接收与实盘推进通过（TCP整个套件因正常心跳280ms未通过）；RA06诊断完成但历史根因未证实；RA07入口交付。新增 **RA-UI01/P2**：正常Qt主循环5分钟UDP/TCP心跳峰值434/2364ms，200ms门槛未通过，原因与产品代码归因未证实，保持打开。

真实串口1小时/拔插/占用/流控、高波特率；两机2.5G矩阵和正式设备负载；持续高吞吐磁盘饱和；干净Windows；原Qt Socket原因，在现有条件下继续列为阻塞。RA02的5分钟实盘基线不能关闭整个AC-010～012、NFR-011。
