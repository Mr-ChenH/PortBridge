# RA-UI01 界面响应修复计划

目标是关闭本机持续负载下超过200ms的GUI心跳问题；保留原始UDP434ms/TCP2364ms失败，不提高门槛、不用短跑替代长跑，不把本机结果扩展成物理2.5G/磁盘饱和认证。

| 编号 | 工作 | 状态 / 完成条件 |
|---|---|---|
| UL01 | 定位不受预算约束的等待 | 已完成受控对照：空间查询发布结果后延迟线程退出1200ms，旧GUI轮询join产生超过1秒心跳；修复版不等待OS线程退出。自然历史长间隔的全部系统外因没有逐一追溯。 |
| UL02 | 修复后台任务生命周期 | 已实现：空间查询、采集导出、样本导出、删除分别复用按需启动的工作线程；每类最多1个执行中与1个排队任务。GUI只消费已发布结果；关闭取消待执行任务，按每类1秒等待任务循环结束，超时由独立状态继续持有任务，不join原生线程。 |
| UL03 | 减少重复布局与详情生成 | 已实现：采样/任务轮询50ms；自动指标/诊断250ms；显式操作与状态切换立即刷新。诊断一次设置文本。空详情不重复清空；不可变选中记录的持续索引、页码和主题匹配时不重复生成。路径变化时空间结果立即失效。 |
| UL04 | 完整回归与实际负载 | 已完成完整CTest10/10、原生UI42/42、队列/安全关闭/详情回归及1200ms退出延迟对照。UDP/TCP各5分钟心跳152/43ms，全部采集字节/尾部/元数据校验；实际三屏与主动GUI500ms停顿复验也通过。正常心跳门槛始终小于200ms。 |
| UL05 | 证据与独立交付 | 验收和88输入冻结已完成，报告与源哈希已更新；新目录与ZIP按独立部署流程验证，包结果见包回执。旧部署/ZIP/失败保留，不提交或推送Git。 |

生产实现见 `src/ui/background_worker.hpp`、`src/ui/main_window.cpp`；回归见 `tests/test_ui.cpp`。可重复受控退出验证新增 `tools/acceptance/storage_exit_probe.cpp` 与 `python scripts/validate-local-acceptance.py --suite ui-exit`。探针只改子进程IAT，不改变系统、DLL文件或运行中的旧交付程序。

最新机器证据在 `docs/validation/ui-latency-fix/`；最终说明见 [修复报告](../reviews/ui-latency-fix.md)。受控注入证明缺陷路径及修复效果，不能冒充实际异常OS永久故障。真实串口、双机2.5G、干净Windows与原Qt Socket调查的外部条件保持未具备。
