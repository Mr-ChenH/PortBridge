# 全界面字体与主题可读性修正

本轮响应“审核整个界面UI”及“深浅主题文字看不清、字体太小”，以已发布的 `87d5fd4` / `http-clarity-fix-1` 为基线。审核与实施由当前代理完成，范围为实际 Qt Widgets 界面；没有新增独立代理审核。

## 范围与发现

| ID | 范围 | 问题及影响 | 修正 |
|---|---|---|---|
| UR01 | 全局、通信工作台、按钮、表头、状态栏 | 应用基础字体为9pt，局部CSS大量8–11px；阅读说明、数值单位和发送选项困难。 | 默认正文16逻辑px，辅助文字至少14逻辑px；同步CSS、等宽编辑器及自绘控件，保留较大的标题/统计数字。 |
| UR02 | 深浅主题 | 次要文字过暗/过浅；仅设置窗口palette不足以控制样式表下的占位文字，仍呈现默认弱化颜色。 | 提高次要文字对比度，补齐活动/非活动/禁用palette，并使用Qt 6.5起支持的 `placeholder-text-color` 明确所有编辑控件的占位颜色。 |
| UR03 | 字节详情、收发记录 | 放大字体后旧偏移列、方向徽章、详情宽度不够。 | 加宽偏移及详情区，增加徽章绘制高度，调整时间/字节列和表头高度；维持原始字节、8字节/行及分页行为。 |
| UR04 | 通信发送区 | 紧凑窗口下字号增大压缩“展开编辑”的实际空间。 | 展开编辑以及高度小于850DIP的紧凑窗口收起大号统计区和趋势，保障收发记录及编辑框可读；收起编辑/恢复正常窗口后恢复。通信、内容、周期发送和原有状态栏继续保持。 |
| UR05 | HTTP / WebSocket | 原有方法列、历史时间/状态列及历史面板默认宽度不适合较大字号。 | 加宽方法、历史列与面板，保留历史/详情分隔条；缩窄时页签可滚动。 |
| UR06 | 工作流 | 独立CSS及自绘节点仍为8–13px，标签与摘要区域小，文字容易省略或裁切。 | 放大节点库、表单、结果、日志、节点标签及摘要；节点改为248×至少146逻辑px，调整文字与端口标签区域。已有节点位置不重写，图可平移/缩放。 |
| UR07 | HTTP设置、创建、命令弹窗及断言 | 部分独立样式/系统等宽字体绕过统一字号；断言来源/关系列过窄。 | 独立设置与创建窗口使用统一字号/占位颜色，浏览器预览使用16px等宽字；加宽断言列。命令窗口继承主窗口统一样式。 |

本轮直接检查的页面包括通信（串口/TCP/UDP配置、发送、记录/字节详情、诊断）、HTTP、WebSocket、工作流、命令库、采集文件及HTTP设置/创建/命令对话框。字号和对比度调整不改变协议栈、数据schema或自动通信规则。

## 验证方法与记录

`before/` 是本轮从基线构建程序取得的12张原生页面截图。早期检查保留在各 `before-*` 目录：首次驱动指定了不存在的测试槽；随后发现样式表字体继承和紧凑展开问题。透明编辑器的palette Base可能是NoBrush，其颜色值为黑色，因此对比度探针改为读取实际绘制背景；这些失败日志不改写为通过。

新增 `wholeUiReadabilityAcrossThemes` 遍历六大页面、两种主题、桌面/紧凑尺寸，检查实际可见文本控件字体至少14px，并对输入/预览控件的文字与占位文字进行4.5:1对比度检查。背景取整窗实际渲染像素，避免把透明样式的palette颜色误当作显示背景。它也验证切页与换主题后没有启动通信。

最终构建、相关完整套件、Qt Windows软件缩放1/1.25/1.5、原生截图以及部署/解压验证结果记录于 `docs/validation/ui-readability/final/` 和相邻receipt文件。软件缩放不等于所有物理屏幕认证；基于控件样式和代表截图的检查不宣称每个字形、每个瞬态弹窗和任意系统配置都已穷尽。

Qt样式属性依据：https://doc.qt.io/qt-6/stylesheet-reference.html#placeholder-text-color-prop ，本轮读取返回HTTP 200，文档注明自Qt6.5提供，本项目为Qt6.8.3。
