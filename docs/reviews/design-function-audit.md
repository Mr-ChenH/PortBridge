# PortBridge 设计一致性与功能完成度审核

> 本文为 `ui-refinement-2` 修复前审核快照，失败证据保留。后续 `audit-fix-1` 的修复及最新验收见 [审核修复验收](audit-fix-acceptance.md)。

审核对象：0.1.0 / `ui-refinement-2`。结论：主要通信能力已经实现，但当前界面尚未严格匹配设计，首版功能也不能判定为全部完成。本次实际复现 7 个问题，并确认若干需求/UI 缺口。此前的全绿测试和交付说明不能覆盖这些新增发现。

本轮只做审核与证据留存，未修复产品代码、修改原型或替换发布包。32 个交付源文件哈希全部匹配原清单；部署 EXE 与 Release EXE 一致。见 [审核元数据](../validation/design-audit/audit-result.json)。

## 与设计页面的主要差异

整体 60px 顶栏、54px 工具轨、232px 侧栏、246px 检查器、石墨/青绿主题和主要分区已经接近设计，但下列结构和交互差异仍明显。此表只比较布局/信息层级；真实空状态、localhost、未知网卡速率及未知持续写盘能力不属于视觉缺陷。

| 区域 | 设计页面 | 当前 Qt 界面 | 判定 |
| --- | --- | --- | --- |
| 连接配置协议 | 标题旁只读协议标记 | 已有 `SERIAL / TCP CLIENT / TCP SERVER / UDP`，侧栏不再有“通信方式”字段 | **已符合用户最近纠正**；新建/编辑方案对话框保留通信类型是正确行为 |
| 连接动作 | 紧跟基础参数，位于“高级参数”上方 | 按钮固定在侧栏很靠下的位置；1440×1000 UDP 截图上约 y=849，设计约 y=698 | 位置与操作顺序未匹配；应维持小窗口可达性后调整 |
| TCP 客户端字段 | 目标地址→目标端口→本地网卡地址 | 本地 IPv4→本地端口→目标地址→目标端口 | 未按协议重组字段；当前额外本地端口可放高级设置，不能破坏绑定能力 |
| 左侧方案区 | 4 个方案后直接进入配置 | 多一排编辑/删除/保存/导入/导出图标，将连接配置整体下推 | 功能合理，但布局不一致；可收进方案上下文菜单/更多菜单 |
| 标题/指标 | 紧凑状态徽标；数字、单位和说明层级鲜明，指标有小标签 | 状态徽标更大，数字字体/字重不同，多个小标签未呈现 | 细节尚未匹配；未知值不应为了视觉变成示例数字 |
| 数据工具条 | 数据/诊断标签与搜索在上一行；HEX/文本入口在下方显示提示旁 | 增加文本流标签、来源/HEX/文本搜索类型，显示格式/暂停/统计重置集中在上方 | 能力更丰富但密度与层次不同；应保留搜索语义和统计重置能力 |
| 字节检查器 | 独立 OFFSET/HEX、范围说明和 ASCII 区域，短预览；仅视觉强调前 4 字节 | 大段 8 位偏移 HEX 放进单个文本框，最多 4096 字节；ASCII 接在全部 HEX 之后，1472 B 数据时默认看不到 | 高优先级视觉/可用性差异。应独立分区、明确预览范围；不能把原型强调误当协议解析 |
| 采集设置 | 字段分组，轮转/时长并列；容量估算有明显底色 | 标签与控件水平排列、逐行堆叠，路径显示较窄，估算为普通文本，增加记录队列预算 | 布局未匹配，真实可用空间和“持续写入未知”是正确实现 |
| 丢失诊断 | 分隔线组成紧凑纵向层级 | 六个带背景边框的较高行/卡片，底部需滚动，完整说明需展开 | 不符合规范“分隔线、工具条和面板”的紧凑层级；增加网卡/内核未知层是正确的 |
| 发送区 | 可点击快捷命令直接在底部排列；持续/有限次数；换行显示“无” | 快捷命令和历史为下拉框+载入；只有有限次数；换行显示 `none` | 周期为实际缺口 A04；其他为可发现性、布局和中文文案差异 |
| 命令库 | 右上新增；每行 HEX/TEXT 标记、名称/内容、右侧载入和删除 | 顶部一排全局按钮，先选中行再操作；统一终端图标，文本中混排格式/编码/换行 | CRUD/载入已实现，但交互方式和层级不匹配 |
| 采集文件页 | 文件类型标记、清晰元信息、每行导出、右上返回 | 顶部全局导出/选择文件按钮，行内无操作，原始文件名/路径占主导 | 功能可用一部分，元信息缺失 G03，刷新有缺陷 A05 |
| 编辑对话框 | 中文“保存命令/取消”，字段垂直排列、有内容标签和提示 | 系统按钮显示 Save/Cancel，字段横向排列，命令正文缺少可见标签，HEX 状态仍显示编码 | 对话框布局与本地化未完成；新增编码/换行能力应保留 |

默认方案名称、设备数、端点、速率曲线、RX 行数和原型示例不同是预期的真实数据差异。本轮没有建议把模拟串口、2.5G/286.4MB/s、740MB/s 磁盘速度、假采集文件或默认预装测试指令写入产品。

## 修复顺序与重新验收条件

1. 先处理 A01/A02/A07 的方案切换数据/错误归属，并统一选择、清空、删除、新建、导入路径的 UI 生命周期。
2. 修复 A03/A05/A06，补齐持续周期发送 A04；再补 TX 速率、截断计数和采集元信息。
3. 按上述对照调整连接配置、检查器、采集设置、文件/命令页、编辑对话框；保留真实数据来源、额外必要能力和小窗口可达性。
4. 将 7 个针对性复现转为正式回归，补缺口验收；重跑全套测试，并在同尺寸/同状态下复核原型与原生截图。全部通过后更新验收文档和发布包。
