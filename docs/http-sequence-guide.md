# HTTP 响应断言与顺序联调

第二期 `http-sequence-1` 在HTTP项目工作台中加入请求断言和已保存请求的顺序运行。后续修复版本 `http-sequence-fix-1` 补齐顶层数组路径和变量展开后的断言校验。运行仍使用原HTTP客户端、当前项目和环境。配置/导入/保存不会通信；明确点击“发送请求”或“运行选定请求”才开始。

## 响应断言

在请求的“响应断言”页签添加规则，保存请求即可保留规则。来源支持状态码、响应头和JSON字段路径（如 `$.data.items[0].id`、顶层数组 `$[0].id`、多层数组 `$[0].items[0][0].id`），关系支持“等于”“存在”“包含”。“等于”按JSON类型比较：数字 `200` 与字符串 `"200"` 不相同；“包含”要求字符串；“存在”不需要预期值。

预期值填写JSON：状态码填写 `200`，字符串填写 `"application/json"`，布尔填写 `true`，对象/数组也可填写。字符串预期值支持 `"{{variable}}"`，发送时展开。展开后的整组断言会重新校验64KiB有界JSON估算预算和深度限制；首步超限不会发出请求或进入资源切换确认，后续步骤超限按停止/继续策略处理，且不发送该步骤。规则最多32行，禁用行也计入编辑预算。字段不存在、无效规则/JSON或未定义预期变量不会被当作成功。

单独发送后的“断言”响应页签展示每条通过/失败；读取权威响应，不依赖被遮蔽或分页的预览。界面和报告省略实际字段值与预期值；响应历史仍可按原有遮蔽预览检查网络返回。

示例 [login-sequence.pbhttp-project.json](examples/login-sequence.pbhttp-project.json) 提供登录提取与查询模板及状态码/字段存在断言。导入后配置自行启动的服务地址和敏感password，再在顺序联调中选择登录、查询；导入不会执行。

## 登录与后续查询顺序执行

1. 保存登录请求：无认证，在“响应提取”中配置 `access_token` → `$.data.access_token`，可添加状态码等于200和token字段存在断言。
2. 保存查询请求：认证选择继承项目，公共Bearer填 `{{access_token}}`。项目/环境地址和变量配置方法见 [项目指南](http-project-guide.md)。
3. 点击HTTP页右上“顺序联调”，勾选当前项目中要执行的请求；选中一行，用“上移/下移”调整顺序。勾选前先确认登录排在查询之前。未保存编辑不参与运行。
4. 默认遇错停止；需要检查其余请求时勾选“失败后继续后续请求”。点击“运行选定请求”才发送；如已有其他活动，沿用原资源切换确认。
5. “联调结果”页签显示逐步通过、失败、取消、跳过和HTTP状态。运行中的主按钮变为“停止联调”，Ctrl+Enter也停止；Esc取消当前HTTP操作并结束整段联调。已发送数据无法撤回。
6. 点击“导出联调报告（值省略）”保存JSON结果。报告只包含运行/项目/环境/请求ID、状态、计数、耗时与断言结果；不包含请求URL、Body、实际或预期字段值、变量值或凭据。结果不会自动持久化。

每步请求定义在开始时冻结，当前步发送时解析变量，匹配响应完成原子提取后再解析下一步。只有2xx可更新提取变量；2xx的断言失败仍执行已经配置的成功响应提取，之后由失败策略决定是否继续。非2xx、网络错误、模板解析、提取失败、断言失败均使该步失败；未执行步骤标记跳过。

环境/项目和编辑在运行期间锁定；步骤间也保持HTTP资源活动身份。外部直接修改环境或变量版本会终止运行，过期/取消响应不能提交token或启动下一步。资源确认期间身份变化会保留旧活动；拒绝确认不会执行后续请求。最多128步、模板总计8MiB，运行最多10分钟；没有隐式重试、循环或自动刷新。

项目版本2和单请求版本1格式保持兼容，新增可选 `assertions` 数组；旧请求没有断言仍可使用。项目导出保留模板断言，敏感字段的实际预期值遮蔽，建议用变量引用或“存在”。顺序选择与报告属于本次运行，不进入项目配置。
