# PortBridge 功能调研与 Qt/C++ 技术路线

## 1. 调研结论

建议定位为“统一串口与 TCP/UDP 收发、可记录并复现调试过程的桌面工具”。首版重点是稳定的通信和一致的调试体验，后续增加桥接、协议解析及自动化。

建议技术组合调整为：Qt 6 + C++17 + Qt Widgets + 独立 C++ 通信核心 + Qt SerialPort + CMake。网络优先评估 standalone Asio；Qt Network 作为对照后端，Windows 原生 Winsock/IOCP 及 RIO 为必要时的专项优化候选。具体后端依据目标硬件上的压测结果确定，不假设更换网络库就能消除丢包。

用户补充：TCP 和 UDP 都需支持，使用约 2.5G 网口，并遇到报文丢失。高速接收、显示抽样、二进制记录与丢包定位因此进入首版设计，原来的低流量基线仅保留为功能冒烟验证。网口速率不是已测应用吞吐量；具体报文大小、包率、平台和实际满速需求仍待明确。专项方案见 [高速通信方案](10-high-throughput-plan.md)。

本报告依据公开产品介绍和 Qt 官方文档形成，未实际安装测试竞品；功能优先级和架构建议属于针对 PortBridge 的工程判断。部分搜索请求超时或失败，但以下核心产品页与通信 API 文档已成功获取。

## 3. 功能范围与优先级

P0：首版必做；P1：第一轮增强；P2：按实际业务选择的专业扩展。

### 3.1 串口

| 功能 | 优先级 | 要点 |
| --- | --- | --- |
| 端口枚举与刷新 | P0 | 显示端口名、描述；有信息时显示厂商、VID/PID、序列号；允许手动输入端口路径 |
| 通信参数 | P0 | 常用及自定义波特率；5/6/7/8 数据位；校验、停止位、无/硬件/软件流控；不支持组合给出明确错误 |
| 打开、关闭、状态与错误 | P0 | 区分占用、无权限、设备不存在、设备拔出、配置失败；过滤 NoError |
| USB 虚拟串口 | P0 | 通过系统串口驱动访问，不需另造 USB 通信栈 |
| 热插拔观察 | P1 | 定时重新枚举并比较差异；自动重连时谨慎匹配身份，不能仅按旧 COM 号连接 |
| DTR/RTS、控制线状态、Break | P1 | 支持情况由硬件与驱动决定；启用硬件流控时禁止手动控制 RTS |
| RS-485 适配 | P1 | 首版使用自动方向控制适配器；手动 RTS 方向控制需要额外验证驱动与时序 |

RS-232/422/485 是电气接口类型；Qt 主要控制操作系统暴露的串口，电平转换与收发方向往往由外部适配器负责。

### 3.2 TCP/UDP 网口

| 功能 | 优先级 | 要点 |
| --- | --- | --- |
| TCP 客户端 | P0 | IP/域名、端口、连接/取消/断开、应用级超时、展示实际本地与对端地址 |
| TCP 服务端 | P0 | 绑定本地地址/端口、启动/停止、客户端列表、选择某个客户端发送或广播；记录来源与连接身份 |
| UDP 收发 | P0 | 本地绑定地址/端口和目标地址/端口独立配置；显示每个数据报的来源、长度；允许零长度数据报 |
| IPv4 和本地网卡地址选择 | P0 | 支持多网卡设备联调；不能只展示计算机的一个 IP |
| UDP 广播 | P1 | 选择正确的网络接口及广播目标；适合设备发现测试 |
| UDP 组播 | P1 | 加入/退出组、接口选择、TTL、回环选项 |
| IPv6 | P1 | 地址输入、绑定、显示与组播接口范围一并验证 |
| TCP 自动重连 | P1 | 明确开关、延时/退避；手动断开和关闭页面必须停止重试，不自动重放旧指令 |
| 心跳与自动应答 | P1 | 根据用户配置发送，区分应用层心跳和 TCP keepalive |
| TLS | P2 | 若业务需要，按最终网络后端选择 TLS 实现，验证证书及所需运行时；不能让高速后端隐式回退至未经验证的路径 |

UDP 界面状态使用“未绑定/已绑定/错误”，不把本地 socket 可用解释成对端在线。“网口助手”默认是应用层 TCP/UDP 调试，原始以太网抓包属于另一类需求。

| 历史与快捷命令 | P0 | 首版命名命令、独立格式/换行设置、保存和单条发送 |
| 多条循环命令序列 | P1 | 顺序、延时、循环次数、启用状态；仅延时序列和等待响应的事务要分开 |
| 日志及导出 | P0 | 普通模式支持文本/结构化导出；高速模式原始二进制分块记录和元数据索引，离线转 HEX/文本；磁盘或队列不足必须报告 |
| 配置保存 | P0 | 连接参数、界面偏好、快捷命令；启动恢复配置但不自动连接或发指令 |
| 多会话标签 | P1 | 每个会话拥有独立连接、显示缓存、命令任务、统计和日志；底层第一版按会话隔离设计 |

### 3.4 高价值扩展

1. **串口 ↔ TCP/UDP 转发（P1）**：符合 PortBridge 的名称和典型联调需求。必须定义方向、TCP 客户端/服务端角色、断线策略、队列上限、慢端背压；串口流转 UDP 时配置聚包规则（最大长度/空闲超时等），不能直接依赖 readyRead 次数。默认两端断线即停止转发并报告，避免重连后发送过时控制命令。首轮支持一对一，服务端多客户端路由后置。
2. **协议分帧和解析（P1/P2）**：P1 可做固定长度、分隔符、帧头+长度字段；必须设最大帧长和异常恢复规则。P2 增加字段类型、大小端、缩放系数与校验结果。未启用分帧时标注“接收块”，不称为协议帧。
3. **自动应答（P1）**：规则匹配原始字节/文本并回应，用于设备模拟；要处理跨读取块的匹配，避免回显循环。
4. **Modbus RTU/TCP（P2，工业场景可提前）**：使用 Qt SerialBus 的 QModbusClient 系列；需要独立需求定义寄存器类型、地址基数、功能码、超时重试和主从角色。Qt 对具体服务端传输的支持需另行核查，不能承诺所有 RTU/TCP 主从组合。
5. **日志回放与测试序列（P2）**：观察回放和向真实设备重放必须分开；后者需要用户主动启动并明确目标。
6. **曲线（P2）**：先确定数值提取协议，再选图形库；纯字节流无法直接生成有意义的曲线。
7. **脚本、ANSI/VT100、MQTT/WebSocket/HTTP、USB HID（P2）**：存在实际场景再投入，避免首版演变为通用网络测试平台。
8. **已被其他程序打开的串口监听、原始网络抓包（独立评估）**：QSerialPort 独占打开串口，普通 Qt API 不能直接旁路监听；通常需要驱动或抓包库及不同权限/部署方案。

## 4. Qt/C++ 技术路线

### 4.1 技术选择

| 项目 | 建议 | 原因与约束 |
| --- | --- | --- |
| UI | Qt Widgets | 适合参数表单、日志视图、表格、菜单和快捷键；开发调试路径直接 |
| Qt Quick/QML | 备选 | 若将来需要触控、复杂动画或大量定制视觉再考虑；当前无此要求 |
| 语言 | C++17 起步 | 满足 Qt 6 基础要求；若团队已统一 C++20 可采用，不因本工具强制升级 |
| 构建 | CMake + Ninja 或相应 IDE 生成器 | 支持 Qt 官方构建接口及跨平台；Windows Qt SDK 和 MSVC/MinGW ABI 必须匹配 |
| 基础模块 | Core、Gui、Widgets、SerialPort；Network 可选 | Qt 负责界面及串口；网络核心独立，Qt Network 用于对照后端或必要的辅助功能 |
| 网络核心 | standalone Asio 优先评估；平台原生后端可替换 | 独立 I/O 执行环境；Windows 异步 Socket 通常走 IOCP，Linux 通常走 epoll；性能须实测 |
| 验证 | Qt Test、CTest | 数据转换、调度和通信回环集成测试 |
| 设置 | QSettings | 用户级偏好和最近配置 |
| 交换配置 | QJsonDocument + QSaveFile | 可分享的命令/连接方案；添加 schemaVersion 和合法性校验 |
| 编码 | QStringDecoder/QStringEncoder | 对字节流进行有状态解码，处理中文字符跨读取块 |
| 旧中文编码 | Core5Compat/QTextCodec 或经验证的 ICU 构建 | Qt 6 基础转换器保证的编码不包括 GBK；不依赖机器的默认代码页实现显式 GBK |
| 日志 | 后台二进制分块文件 + 元数据索引 | 高速热路径不对每个 payload 转 HEX/JSON；普通记录和离线导出仍可使用文本/JSONL；先不引入 SQLite |
| 部署 | Windows windeployqt；其他平台单独打包 | 在未装 Qt 的干净环境验证运行时与插件；打包清单依赖最终 Qt 版本和模块 |

Qt 版本建议固定一个实际可安装、可分发的 Qt 6 小版本。6.8 是兼容基线候选，不代表当前最新版本，也不代表所有维护更新都无需商业许可。本报告没有检查本机 Qt SDK。若采用较旧基线，不使用仅在 6.9/6.10 新增的 API，例如 QSerialPort::setWriteBufferSize 是 6.10 才引入，应用自己的发送队列仍需限流。

### 4.2 模块划分建议

- **界面层**：连接参数、通信视图、发送面板、客户端列表、设置页。仅主线程操作 QWidget。
- **会话层**：SessionController 管理状态、统计、发送任务和记录；与页面生命周期分离。
- **传输层**：SerialTransport、TcpClientTransport、TcpServerTransport、UdpTransport。统一启动/停止/发送/收数据接口，同时保留传输能力差异；接口与 Qt Socket 解耦，允许 Asio 和原生实现。
- **高速管线**：独立 I/O 执行环境、复用数据块、有界队列、后台记录、显示抽样；原始接收不依赖 UI 线程或逐包 signal/slot。
- **数据工具层**：HEX 编解码、文本有状态编解码、校验、未来分帧器。核心逻辑独立于界面，便于测试。
- **日志与配置层**：TraceWriter、SettingsStore、ProfileStore。
- **增强层**：BridgeController、CommandSequence、ProtocolDecoder 按后续范围加入。

建议收到的数据记录包含：会话 ID、连接 ID/来源端点、方向、原始字节、时间、记录序号和记录类型。UDP 增加数据报标志；TCP 服务端按每个客户端保存独立解码/分帧状态；显示字符串只是原始记录的派生结果。

传输接口不能只定义 send(QByteArray)：还需可选目标，才能表达 TCP 服务端指定客户端和 UDP 目标地址。统一抽象应保留“字节流/数据报”“监听/连接”等能力。

### 4.3 线程与异步 I/O

根据 2.5G 网口场景，网络 I/O 从首版起与 GUI 线程分离。Asio 后端使用独立 io_context 执行线程，Qt 对照后端的 socket 位于有事件循环的工作线程。所有对象在其所属执行环境内创建、读写、关闭；关闭和取消要等待在途操作正确回收。串口亦与显示/记录解耦，QSerialPort 性能需按实际串口波特率另行验证。

接收回调仅完成读取、轻量元数据和数据块交接，不能进行 HEX 格式化、同步落盘或等待 UI。工作线程至 UI 传递的是有限的显示批次和统计快照，不能通过无限 queued signal/slot 事件队列运送所有原始数据。线程数按负载评估，不按客户端数直接创建。

Qt Socket 对照实现采用 readyRead、bytesWritten 等异步信号，不在 GUI 线程调用 waitFor...。增加线程或更换库都不能替代容量设计和过载策略，详细要求见高速通信方案。

### 4.4 数据显示与日志

首版可使用有块数限制的 QPlainTextEdit，注意单个超长无换行文本也需要字节/字符上限；若采用表格化记录，可使用 QAbstractTableModel + QTableView 和有界记录缓存。HEX 显示会放大数据体积，内存预算应同时考虑原始数据、格式化字符串和视图。

按约 30–60 ms 批量更新视图，具体值以体验和负载测试调整，不对每个字节触发 UI 更新。自动滚动可关闭；暂停显示时只保存有限的待显示内容，恢复后标明裁剪情况。

日志在渲染和过滤之前接收原始记录。普通模式结构化日志可包含 schemaVersion、sequence、sessionId、connectionId、timestamp、direction、transport、peer、payloadHex、event。高速模式采用二进制块和长度/来源/时间等元数据索引，保留 UDP 数据报边界，并在离线导出时生成 HEX/JSON。文件失败或队列溢出必须告警并记录可观察的丢弃计数；显示抽样与原始记录丢失分别统计，不能承诺无限负载下永不丢数据。

### 4.5 容易出错的细节

| 问题 | 正确处理 |
| --- | --- |
| TCP 粘包、半包；串口分段 | 字节流缓存与显式分帧；绝不把 readAll 一次的结果当作一条协议报文 |
| UTF-8/GBK 中文拆分 | 每条流/连接维护增量解码器；断线重置，切换编码基于原始缓存重建显示 |
| UDP 数据报丢失边界 | 用 receiveDatagram，读取待处理数据报；保留来源，避免过小接收上限导致截断 |
| write 返回值 | 检查错误、部分接受和剩余数据；区分排队、本地写出、对端业务应答 |
| 循环发送积压 | 队列有上限、拥塞时暂停或拒绝新的周期任务并提示；不盲目追赶错过周期 |
| TCP/串口流量过大 | 接收及时、处理分批、发送背压；串口无流控/UDP 超载时仍可能丢失，必须测试和提示 |
| 人为断开又被自动连接 | 显式用户意图和重试状态；取消待连接与待重试任务 |
| 串口拔出 | 处理 ResourceError；停止发送，记录状态，后续重连验证设备身份 |
| TCP 服务端会话混淆 | 每条连接独立 ID、缓存、状态；IP/端口展示不能代替稳定内部身份 |
| UDP 收发成功误报在线 | 本地成功只表示本地操作成功；在线判断需要应用层应答 |
| 高频精确时序 | QTimer 受调度影响，不能提供硬实时微秒精度 |
| 串口硬件信号差异 | 以驱动返回值为准，UI 标明不支持；不要强行承诺全部平台相同 |

## 5. 页面组织建议

首版以通信类型入口或单个活动会话起步，底层保留会话隔离；需要同时对照多个设备时再开放多标签。

- 左侧/顶部：串口、TCP 客户端、TCP 服务端、UDP 的参数和启停按钮。
- 中部：接收/发送记录，工具条提供 HEX/文本、时间戳、自动滚动、搜索、暂停、清空、记录。
- 底部：输入编辑器、编码/HEX 模式、换行、发送、周期发送和快捷命令。
- TCP 服务端附加客户端列表及明确的发送目标。
- 状态栏：连接/监听/绑定状态、TX/RX 统计、速度、待发送量、日志状态和错误提示。

避免把“清空显示”“重置计数”“清除设备缓冲”“停止日志”合成一个操作。

## 6. 分期建议

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 第一阶段：性能验证与基础闭环 | 先验证 2.5G 目标链路下 TCP/UDP 后端和原始记录管线，再完成串口及共用调试功能；首版增加高速模式、抽样显示、二进制记录与丢包统计 | 确定可复现的吞吐/包率上限和丢失位置；四种传输可收发，异常可恢复 |
| 第二阶段：效率增强 | 多会话、文件发送、多命令序列、旧中文编码、重连、串口/网络转发、校验、UDP 广播/组播 | 并发会话隔离；背压与转发边界清楚；命令配置可导入导出 |
| 第三阶段：场景专用 | 自定义协议解析、Modbus、自动应答增强、曲线、回放、脚本、TLS 等 | 按真实设备与协议独立定义并验收 |

如果主要面向工业现场，Modbus 可提前；如果主要用于网关调试，转发可提前。当前建议采用通用调试工具范围，未把这些场景假设当作用户决定。

## 7. 验证路线

- 纯逻辑：严格 HEX、换行、编码跨块、发送队列、定时停止、配置版本/合法性校验。
- TCP：本机回环服务器/客户端，强制切分与合并字节，多个客户端独立状态、广播、远端断开与端口占用。
- UDP：本地回环，连续多数据报、零长度报文、多个来源、保持边界；第二阶段验证广播和组播。
- 串口：可先用虚拟串口对验证；发布前使用真实 USB 转串口进行字节回环、占用、拔插、高波特率与流控测试。虚拟串口不能证明真实硬件时序与驱动行为。
- 性能：按 2.5G 场景使用两台真实机器和实际网卡，分别测不同报文大小/包率、突发和持续负载；分开测仅接收、接收+记录、接收+显示、全部开启。对照 Qt Socket、Asio 和必要的原生实现，记录丢失位置及最大无应用丢弃负载；回环不能替代真实链路验证。
- 发布：在无开发环境的干净目标系统运行包验证模块、平台插件、编码依赖与基本功能。
