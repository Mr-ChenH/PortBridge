# HTTP项目、环境与认证交互重构

依据用户要求，统一项目、环境、变量与公共认证配置，替代名称创建与多个隐藏弹窗。已有Postman/Bruno等官方调研见15-http-project-research.md；本轮证据来自实际HttpProjectPanel、HttpProjectStore、resolveHttpRequest和现有回归，不新增未执行的外部研究结论。

## 关系与要求

项目拥有请求/分类、项目变量、公共认证与多个环境。环境拥有名称和环境定义。响应提取属于当前项目/环境的运行值，优先级：运行值 > 环境定义 > 项目定义。切换环境仅选择上下文，不改写模板、不发送、不自动登录。请求URL显式引用{{base_url}}；请求认证明确选择继承项目、自行配置或无认证。

| ID | 要求与验收 |
|---|---|
| HR01 | 侧栏明确项目设置、配置环境和环境管理，创建环境后直接进入配置；服务地址映射既有base_url变量，不引入隐式URL覆盖。 |
| HR02 | 同一个设置窗口提供当前环境、项目变量、公共认证、生效变量四区；名称、服务地址与普通变量可直接编辑。 |

| HR07 | 新交互真实Qt回归、真实HTTP继承/切换、深浅及软件缩放视觉验证；完整受影响回归和独立部署包。 |

## 技术与任务

1. Store增加单次保存当前项目/当前环境配置的方法，候选定义与运行值先校验，预算通过后一次commit成功才更新运行值；旧setter继续兼容既有测试和调用。
2. 提取可复用变量编辑表、认证表单和项目设置窗口。不把responseDerived运行值复制进定义编辑表。使用显式“生效变量”面板确认来源。
3. Panel的变量/认证方法作为统一窗口的导航入口；侧栏不再使用含糊“变量”。环境新建先创建空定义（明确操作），立即打开环境配置；取消保留已创建的空环境并显示未配置状态。
4. 名称/服务地址/两个定义表/认证/运行清除一起保存；捕获projectId/environmentId/revision，在保存前检查活动及身份。
5. 请求认证说明与继承类型同步，验证实际Authorization、变量隔离、取消、保存失败和旧数据兼容。

本轮由当前代理实施/自审，不使用未授权的多代理workflow。用户已明确要求重构并继续实现，无新增平台或认证协议范围。
