# 工作流 UI 设计与交互原型

本设计承接 [工作流调研](11-workflow-research.md)，沿用 [PortBridge 视觉规则](04-ui-design.md)。交付包含设计规范、离线交互原型与浏览器验证截图。正式程序仍为 `profile-picker-1`；本轮没有加入 Qt 工作流页面或真实 HTTP/WebSocket 通信。

## 1. 设计方向

目标是让设备联调人员通过节点组合重复任务，并在失败时立即看清“哪个步骤、什么响应、为何失败”。主视图优先提供明确的步骤、资源和运行状态。HTTP 的请求响应、WebSocket 的消息连接、串口/TCP/UDP 的字节或数据报分别表达。

延续石墨底色、薄荷绿主动作及现有 RX 绿色/TX 橙色。HTTP 类节点用蓝色图标，变量/控制类用淡紫色图标，通信发送用橙色图标；分类色只在图标和必要标识中使用，运行状态以文字、边框和符号共同呈现。避免把接口库名称或执行器实现细节放进用户操作路径。

## 2. 页面结构

```text
┌ PortBridge ─ 调试工作台 ─ 采集文件 ─ 命令库 ─ 工作流 ─ 主题 ┐
│ 流程名称 / 保存状态 / 简述                   模板 保存 运行 │
│ 节点库切换 撤销 重做 复制 删除 检查流程     资源状态 参数切换 │
├────────────┬──────────────────────────┬──────────────────┤
│ 节点库      │ 画布                      │ 节点详情          │
│ 搜索        │ 节点 + 命名端口 + 执行线  │ 参数 / 上次结果   │
│ 流程控制    │ 运行状态与问题定位        │ 协议专属表单      │
│ 通信与消息  │                          │ 超时/限额/输出变量│
│ HTTP / WS  │                          │                  │
│ 变量与验证  │ 缩放 / 适应画布           │                  │
├────────────┴──────────────────────────┴──────────────────┤
│ 运行记录 / 运行变量                 状态 暂停后续步骤 停止 │
│ 时间  节点  状态  详情  耗时                              │
├─────────────────────────────────────────────────────────┤
│ 活动流程与资源状态                              全局状态 │
└─────────────────────────────────────────────────────────┘
```

工作流作为第四个主导航入口。进入后，用节点库替代调试工作台的连接参数侧栏，避免两套侧栏争夺画布空间。浏览工作流、采集文件或连接方案不应停止已有通信；已有会话在顶部资源摘要中可识别。运行中资源绑定不会随界面浏览改变。

运行前显示资源计划：使用/借用哪个方案、建立哪个连接、结束时如何处理。若与现有会话或周期任务冲突，在运行区列明受影响的资源及任务，主动作明确写成“停止旧任务并运行”，由显式动作完成替换；普通浏览或检查流程不替换会话。原型没有真实活动会话，这部分作为 Qt 实现要求。

正式版流程名称支持编辑，名称旁有“草稿/未保存/已保存”；模板入口按需打开，不在侧栏永久展示全部流程。流程库/最近流程可在标题选择器中打开，沿用当前连接方案的搜索弹层思路。原型已提供模板弹窗及草稿状态，流程名称与库管理的完整交互留给正式 Qt 实现。

## 3. 布局与尺寸

尺寸为设计用 DIP；浏览器原型使用 CSS px，不能当作原生 DPI 验证。

| 区域 | 建议尺寸 | 行为 |
| --- | --- | --- |
| 应用导航 | 58 高 | 保留既有品牌、导航和主题位置。 |
| 工具轨 | 54 宽 | 工作台、工作流和模板入口；不增加通信方式下拉框。 |
| 流程标题 | 90–110 高 | 名称、描述与主动作；狭窄窗口允许换行。 |
| 编辑工具条 | 42 高 | 常用图编辑与资源状态，切换侧栏。 |
| 节点库 | 210 宽；紧凑时 176 | 独立滚动、搜索、拖入；可折叠。 |
| 参数栏 | 286 宽；紧凑时 264 | 独立滚动；Qt 正式版通过分隔条调整。 |
| 画布 | 剩余全部空间 | 平移与缩放；局部内容超出画布不造成整个窗口横向滚动。 |
| 常规节点 | 208 × 132 | 标题、协议标识、两行摘要、序号与状态；开始/结束为 108 × 76。 |
| 运行区 | 默认 200 高；小窗口 164 | 可拖动调整、折叠；状态和停止按钮保持可见。 |
| 状态栏 | 28 高 | 流程状态、节点/连线数；原型另显示演示场景与离线标识。 |

主验证尺寸为 1440×1000、1280×900、1024×768。低于 900 宽时侧栏改为覆盖面板，按需打开；390×844 是原型的窄屏布局检查，正式 Windows 产品目标仍是桌面窗口。

默认视图保持至少 85% 缩放并定位选中节点，优先保证文本与端口可操作；“适应画布”单独提供全图概览，允许更小缩放。点击运行日志或定位问题会将节点移入可见区域。还可恢复 100%、平移或折叠侧栏。

## 4. 节点库与画布

节点分组：

- 流程控制：开始、结束、延时、条件分支、有限循环。
- 通信与消息：使用连接方案、发送数据、发送并等待、等待消息。
- HTTP / WebSocket：HTTP 请求、WebSocket 连接、关闭连接。
- 变量与验证：提取 JSON 字段、断言结果、设置变量、步骤日志。

搜索匹配节点名称和协议标记；例如 WebSocket 只筛选对应节点，不因为组名而显示整组 HTTP 节点。列表项有统一图标和拖动提示，也可双击添加到视口中心。

画布规则：

1. 从节点库拖入创建；拖动标题/内容移动节点；点击或双击查看参数。
2. 普通出口表示下一步/成功；错误出口用文字标明“错误”或“不通过”。错误出口未连接时按终止失败设计。
3. 从出口拖至另一节点的入口建立连接。端口 hover 呈现方向和结果语义；输入不接入开始节点，结束不提供输出。
4. 同一控制出口首轮仅一条线，禁止自连及普通环路。循环由结构化有限循环表示。
5. 选中连线可删除；选中节点后可复制、删除、撤销和重做。删除节点同时删除关联连线。
6. 空白处拖动平移，滚轮缩放，工具按钮提供放大、缩小、100% 和适应画布。
7. 两行示例使用蛇形布局，第二行反向端口保证连线经过节点间隙，不穿过摘要。
8. 无节点时显示空画布提示和选择模板入口。打开、编辑、拖线、保存与导入不执行通信。

正式版补充框选、多选、对齐、复制整组、连线重新挂接、子流程与视图状态保存。原型实现单项选择、复制、拖入/拖线、撤销与缩放，没有宣称这些高级功能已完成。

## 5. 参数面板

节点详情上部显示图标、名称、节点类型及稳定标识；页签为“参数”和“上次结果”。参数随着选中节点变化，常用字段在前，容量和 TLS 等进阶设置可折叠。名称及参数改动同步到节点摘要。表单本身滚动，页签、关闭按钮与底部状态保持固定。

| 节点 | 主要字段 | 状态与输出 |
| --- | --- | --- |
| 使用连接方案 | 搜索方案、资源归属（借用/流程建立） | 显示实际运行资源；借用连接结束后保留。 |
| 发送数据 | 绑定资源、格式、内容、UDP 请求目标/TCP 客户端目标 | 明确接受、写出和失败；不把发送接受作为对端确认。 |
| 发送并等待 | 发送内容、匹配方式、字段/字节规则、预期值、超时、来源限定 | 响应单独输出；说明先登记匹配再发送，显示暂停不影响等待。 |
| HTTP 请求 | 方法、URL、请求头、body、连接/总超时、响应变量、期望状态 | status/headers/body 与请求错误分开。 |
| WebSocket 连接 | ws/wss URL、握手头、子协议、超时、消息上限 | 显示握手/已连接/关闭/失败；不使用 HTTP 请求的空闲“已连接”状态。 |
| WS 发送/等待 | 文本/二进制类型、编码或变量、完整消息条件 | 保留消息边界；接收帧碎片在协议层装配，不显示为多条业务消息。 |
| JSON 提取 | 输入变量、字段路径、输出变量 | 缺失字段明确失败。 |
| 断言 | 输入字段、关系、期望值 | 通过/失败；显示实际值与期望值。 |
| 有限循环 | 最大次数、体/退出条件 | 可见剩余次数、当前轮次、总截止时间。 |
| 关闭连接 | 资源、关闭码、原因 | 与释放借用资源区分；WS 显示协议关闭信息。 |

HTTP body 是高频操作，原型默认展开 JSON/原文编辑，请求头折叠。正式版可增加键值头编辑、body 模式切换和变量补全。TLS 服务端验证默认开启，相关设置在高级区，与服务器返回业务错误分开表示。

原型 WS 配置已包含 URL、握手头、子协议、超时与消息上限；通用发送节点提供文本、HEX 和二进制变量的格式预留。独立的 WS 文本/二进制类型编辑、完整来源选择、TCP 分帧配置、断言关系及循环体编辑需要在正式版补齐。

## 6. 运行与错误状态

| 状态 | 画布 | 参数与动作 | 日志与资源 |
| --- | --- | --- | --- |
| 编辑草稿 | 未运行、选中描边 | 可编辑；检查/运行可用 | 未连接，不显示虚构收发。 |
| 配置无效 | 定位问题节点 | 显示首条问题和数量，提供定位；阻止运行 | 参数错误不伪装为网络失败。 |
| 执行中 | 当前节点薄荷描边；路径动态提示 | 结构/参数锁定，保存/换模板禁用 | 实时步骤记录；暂停后续步骤/停止可用。 |
| 暂停后续 | 已完成步骤保持可见 | 可继续/停止；当前网络操作仍可完成 | 明确仅暂停后续步骤，不声称冻结网络。 |
| 成功 | 完成文字及标记 | 可再次运行；可查看每步结果 | 结果/变量保留；流程拥有的资源释放。 |
| 超时/断言失败 | 失败节点与文字；后续未执行 | 切到失败节点“上次结果” | 显示超时值、实际/期望和响应，不自动无条件重发。 |
| HTTP 401/404/500 | 是否失败取决于期望状态/后续断言 | 上次结果仍有 status、headers、body | “收到响应不符合预期”与“没有收到响应”区分。 |
| 用户停止 | 当前操作取消，后续未执行 | 编辑解锁 | 明确停止后的清理与资源归属；迟到事件不推进流程。 |

原型提供正常响应、等待超时、HTTP 401 三种演示场景。HTTP 默认期望 200；设置“任意状态”后 401 作为完成的响应保留，再由 JSON 提取或后续断言决定结果。原型也实际对示例运行变量做字段提取及相等断言。

原型按顺序播放固定的模拟协议数据和耗时，不执行真实 I/O。编辑协议 URL 不会访问网络。分支、有限循环和错误出口的结构可编辑，但原型不执行完整分支/循环语义；需要运行时会明确提示。真实资源租约、取消时延和高速匹配属于后续执行器验收。

## 7. 日志、变量与响应

运行区页签为“运行记录”和“运行变量”。记录列：时间、节点、状态、详情、耗时。点击记录定位节点并打开上次结果；可从成功步骤查看 HTTP body，也可从失败步骤查看错误及收到的数据。

变量区按名称、类型和值排列。原型对 token 独立变量遮蔽显示；正式版需要对响应、日志、导出等所有视图的敏感字段建立统一遮蔽策略。原型使用固定演示 token，无真实凭据。

响应区首行突出成功/失败与耗时，下方展示运行/节点标识和结构化响应；正式版 HTTP 增加 Body/Headers 页签，WS 增加文本/HEX/UTF-8 页签及关闭信息。保留完整原始字节的有界分页规则，不为工作流再造无界内容面板。

步骤日志独立于工作台 RX/TX 数据样本，不能将节点启动/结束描述混进 UDP 原始记录。运行区折叠后保留状态、停止与展开入口。其高度可以鼠标拖动，也支持分隔条上/下键调整。

## 8. 模板与保存

模板弹窗包含：

- 设备登录与订阅：HTTP → 提取 token → WS → 发送等待 → 断言 → 关闭。
- UDP 指令响应：使用方案 → 发送等待 → 断言 → 结束。
- 空白流程：从零组合。

替换模板可撤销，默认不运行。原型保存草稿到当前浏览器，恢复通过操作说明中的“恢复已保存草稿”显式触发；不自动恢复运行。说明弹窗可导出标记 `prototypeOnly: true` 的设计 JSON，该文件尚不是正式程序可导入的文件。

正式版采用 `.pbflow.json`，提供导入、另存为、最近流程、修改后离开提示、节点版本迁移及不支持节点的说明；与调研中的稳定资源 ID/配置迁移一并实现。

## 9. 快捷键与可访问性

原型支持 Ctrl+Z、Ctrl+Shift+Z、Ctrl+D、Ctrl+S、Delete，输入框内保留文本编辑键。端口、图编辑工具、主题和分隔条有可访问名称及可见焦点；侧栏关闭时不留下可聚焦的隐藏表单。状态除颜色之外还有文字和符号。系统减少动态效果时停止连线动画。

正式版需要键盘添加节点、端口导航/连接、批量操作和屏幕阅读器的图摘要，并通过 Qt 原生辅助功能检查。浏览器原型不等同于原生可访问性验收。

## 10. Qt 落地映射

| 设计区域 | Qt 实现建议 |
| --- | --- |
| 工作流入口 | 现有导航 + QStackedWidget 新页面，保持后台 controller 生命周期。 |
| 节点库 | QTreeView/QAbstractItemModel；过滤代理；拖动 MIME 保存 nodeType。 |
| 画布 | QtNodes AbstractGraphModel/BasicGraphicsScene/GraphicsView，业务执行器独立。 |
| 属性区 | 按 nodeType 的表单注册、QScrollArea/QFormLayout、JSON QPlainTextEdit。 |
| 分栏 | QSplitter；保存宽度和运行日志高度；小窗口可折叠。 |
| 日志/变量 | QTableView + 有界模型，批量 UI 快照；点击定位稳定 nodeId。 |
| 运行控制 | QAction 状态统一；stop/cancel 异步，不在 GUI 同步等待 I/O。 |
| 模板/文件 | QDialog/QMenu，读取文件不自动启动执行。 |

HTTP 使用 cpr/libcurl，WS 使用 Boost.Beast 的选型不影响 UI 的请求、消息及状态定义。用户看到协议行为，开发者通过统一能力接口适配。

## 11. 已完成原型与验证

入口：[workflow-prototype/index.html](workflow-prototype/index.html)，双击用 Chrome/Edge 打开即可，无 npm 依赖或服务器。它只包含 HTML/CSS/JS；不嵌入正式应用。

第一阶段浏览器检查 **16 项通过**：实际鼠标拖动、节点库 HTML5 拖入、实际端口拖线、连线删除、参数修改与撤销、搜索、模板空态与撤销、四种尺寸溢出和 JS 错误检查。

第二阶段浏览器检查 **30 项通过**：模拟运行成功、响应/变量、超时、401 响应保留及期望状态、停止隔离、暂停恢复、断言/字段提取错误、草稿保存恢复、UDP 模板、静态检查定位、日志拖动/折叠、响应式与零网络请求。准确项目列表以两个 JSON 回执为准。

第三阶段截图审查后的 **17 项检查通过**：四种尺寸默认阅读缩放/选中节点可见/无页面溢出、显式全图概览、窄窗侧栏首次点击展开、1024 窗口失败节点定位及 JS 错误检查。三阶段共 63 项，检查的是原型交互与模拟状态。

修复并记录了节点搜索最初错误匹配整个组、窄窗零宽参数栏保留 1px 边框造成页面宽 391px 的问题。另外截图审查修正了蛇形布局连线穿过节点、默认全图缩放文字过小及窄窗侧栏首击未展开的问题。

证据：[第一阶段](../validation/workflow-ui/phase-1.json)、[第二阶段](../validation/workflow-ui/phase-2.json)、[第三阶段](../validation/workflow-ui/phase-3.json)、[状态截图画廊](../validation/workflow-ui/gallery.html)、[窄窗失败记录](../validation/workflow-ui/phase-2-before-responsive-fix.json)。本轮未做 Qt 原生、125%/150% Windows DPI 或真实协议性能验收。
